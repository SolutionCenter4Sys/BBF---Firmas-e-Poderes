SÍNTESE PARA LIDERANÇA

O que esta arquitetura garante

1. KAAS estrutura. Regras decidem.

O Worker envia o documento ao KAAS (Foursys). O KAAS devolve sócios e poderes. A decisão APROVADO / REPROVADO / MANUAL sai do motor de regras na API (RN01–RN04 + TH01), não do workflow externo.

2. Quatro containers. Uma rede.

web (Next.js), api (.NET 8), worker (.NET 8) e db (PostgreSQL 16) na rede Docker bbf-internal. A API não chama o KAAS. O Worker consome a outbox (tabela no Postgres, não broker).

3. Dois perfis na apresentação.

Operador: upload, consulta e checagem de poderes. Auditor: trilha WORM (append-only) e replay do snapshot persistido — sem reprocessar KAAS.

4. Integração externa única.

KAAS (Foursys), jornada testes-firmas-e-poderes, chave X-Flow-Api-Key só no Worker. Junta Comercial permanece stub. Sem Kubernetes no desenho.
